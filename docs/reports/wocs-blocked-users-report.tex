\section{2. Forensic Methodology \& Detection Criteria}
All metrics in this document were extracted directly from the GitHub REST Search and Issues APIs against \texttt{SatyamPandey-07/WorkSphere} using immutable UTC ISO-8601 timestamps. Accounts were flagged and blocked when multiple independent anomaly signals crossed adversarial thresholds:
\begin{itemize}[leftmargin=1.5em, itemsep=3pt]
  \item \textbf{Inter-Arrival Velocity ($\Delta t$):} Human-authored architectural implementations, local test verification, and documentation require realistic development cycles. Automated scripts exhibit sustained $\Delta t \in [1\text{s}, 90\text{s}]$ across dozens of consecutive PRs/issues.
  \item \textbf{Self-Issue / Self-Assign Bypass Ratio:} WOCS guidelines require claiming curated maintainer issues. Farming scripts bypass curation by creating an issue, immediately self-assigning it, and opening a matching PR within seconds.
  \item \textbf{Entropy & Semantic Validity Check:} Issues titled \texttt{".."} or \texttt{"//"} carry zero engineering specification and exist solely to exploit automated issue-tracking workflows.
  \item \textbf{State-Transition Thrashing:} Repeatedly closing and reopening issues as \texttt{completed} or \texttt{duplicate} after maintainer intervention constitutes active triage sabotage.
\end{itemize}

\section{4. Governance Hardening \& WOCS Remediation Architecture}
In direct response to Code Social's audit (Nov 28, 2026), WorkSphere has deployed a zero-trust, low-maintainer-overhead review and labeling pipeline that guarantees every WOCS PR receives meaningful review and accurate difficulty classification:

\begin{enumerate}[leftmargin=1.5em, itemsep=5pt]
  \item \textbf{Auto-Merge Paused (\texttt{.github/workflows/auto-merge.yml}):}\\
  Removed all automatic triggers (\texttt{pull\_request\_target}, \texttt{issue\_comment}, \texttt{workflow\_run}, and 5-minute \texttt{schedule}). The workflow now runs strictly on manual \texttt{workflow\_dispatch}. Furthermore, automated bot self-approvals (\texttt{pulls.createReview(APPROVE)}) have been removed and replaced with a mandatory check requiring at least one genuine \texttt{APPROVED} review.

  \item \textbf{Strict Documentation Level Cap (\texttt{auto-comment.yml} \& \texttt{auto-label-new-issue.yml}):}\\
  Previously, PRs exceeding 350 lines of Markdown or doc issues containing keywords like \texttt{zkp}/\texttt{solana} were automatically escalated to \texttt{level 3}. Both workflows now enforce:
  \begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item \texttt{auto-comment.yml}: Any PR whose changed files are exclusively \texttt{*.md} or under \texttt{docs/} (or \texttt{docs:} titles without code changes) is strictly capped at \texttt{level 1}.
    \item \texttt{auto-label-new-issue.yml}: Any issue labeled \texttt{documentation} or titled \texttt{docs:} bypasses keyword escalation and is strictly assigned \texttt{level 1}.
  \end{itemize}

  \item \textbf{Automated AI Code Review via CodeRabbit (\texttt{.coderabbit.yaml}):}\\
  Configured assertive automatic reviews (\texttt{auto\_review.enabled: true}, \texttt{request\_changes\_workflow: true}, \texttt{high\_level\_summary: true}) with path-specific WOCS rules checking issue-scope alignment, documentation level-1 compliance, test coverage, and security regressions before maintainer sign-off.

  \item \textbf{GitHub \texttt{main} Branch Protection \& Collaborator Lockdown:}\\
  \begin{itemize}[leftmargin=1.5em, itemsep=2pt]
    \item Audited \texttt{/repos/SatyamPandey-07/WorkSphere/collaborators}: confirmed \texttt{SatyamPandey-07} is the sole admin/write collaborator; external contributors hold \texttt{Read} access only and cannot close, reopen, or cross-assign issues outside \texttt{/claim} and \texttt{/unclaim}.
    \item Enabled branch protection on \texttt{main} requiring \textbf{1 approving review}, stale-review dismissal, and passing CI checks (\texttt{build-and-test}, \texttt{pr-check}).
  \end{itemize}
\end{enumerate}
